# Kaggle Workflow

How to train + run local CV + submit on **Kaggle Notebooks with the RTX PRO 6000 Blackwell** accelerator (96 GB VRAM, single device, native parity with the host eval kernel).

This is the active workflow. The earlier `docs/archive/vertex_ai_setup.md` was abandoned when we discovered the GCP project had no A100-80GB/H100 quota.

---

## Hard constraints (don't break these)

- **Internet must be OFF** in both the training and CV kernels. Competition rules forbid internet-on kernels. All deps come from the public offline-packages Dataset (`dennisfong/nvidia-nemotron-offline-packages`, ~9 GB pre-built wheels).
- **Accelerator must be `RTX PRO 6000 Blackwell`**. `"machine_shape": "NvidiaRtxPro6000"` is baked into both `kernel-metadata.json` files, so the correct GPU is selected automatically on every `kaggle kernels push`. No manual UI step needed.
- **Code Dataset path is namespaced**: Kaggle's newer images mount under `/kaggle/input/datasets/<owner>/<slug>/`, NOT `/kaggle/input/<slug>/`. Same for models (`/kaggle/input/models/<owner>/<model>/<framework>/<variant>/<version>/`).

## Layout

```
kaggle/
  blackwell_setup.py       # Importable helper: rmsnorm + fast-path + ptxas patches
  code_dataset/            # Built by sync script; uploaded to Kaggle
    nemotron-code.tar.gz
    dataset-metadata.json
  train_kernel/            # Generated by build_kaggle_notebooks.py
    notebook.ipynb
    kernel-metadata.json
  cv_kernel/               # Generated by build_kaggle_notebooks.py
    notebook.ipynb
    kernel-metadata.json

scripts/
  sync_code_to_kaggle.py        # bundle + push code Dataset
  build_kaggle_notebooks.py     # emit .ipynb + kernel-metadata.json
```

`kaggle/code_dataset/` is build output (gitignored — see `.gitignore`). The notebooks under `kaggle/train_kernel/` and `kaggle/cv_kernel/` are also build output of `build_kaggle_notebooks.py` but they're checked in so they're directly browsable; if you edit a cell, edit the source in `scripts/build_kaggle_notebooks.py` and re-run the builder.

## One-time setup

1. Confirm Kaggle CLI auth works: `uv run kaggle competitions list | head` (creds live at `~/.kaggle/kaggle.json`).
2. On Kaggle Models, accept the license for `metric/nemotron-3-nano-30b-a3b-bf16` (you already did this manually to access the model) — this is the same base model the host scorer uses.
3. The kienngx CoT corpus dataset (`kienngx/nemotron-30b-competition-trainingdata-cot-labels`) is publicly available; no license accept needed.

## Per-iteration workflow

### 1. Sync code changes to the Kaggle Dataset

After any edit to `nemotron_local_cv/`, `nemotron_train/`, `data/val_split_600.csv`, or `kaggle/blackwell_setup.py`:

```bash
uv run python scripts/sync_code_to_kaggle.py -m "what changed"
```

Idempotent. First run creates `aleixlopez/nemotron-code`; subsequent runs add a new version.

### 2. (If notebook structure changed) Rebuild + push the kernels

```bash
uv run python scripts/build_kaggle_notebooks.py
uv run kaggle kernels push -p kaggle/train_kernel
uv run kaggle kernels push -p kaggle/cv_kernel
```

If you just edited cell contents in `scripts/build_kaggle_notebooks.py`, run both commands. If you only updated package code, only step 1 is needed — the next kernel run pulls the new dataset version.

### 3. Run the training kernel

In the Kaggle UI: open `aleixlopez/nemotron-sft-training`, hit **Run All** (or run a Quick Save). Defaults are a smoke run (200 rows, 50 steps) — bump `sample_n` to `None` and `max_steps` to `-1` in cell 6 for the full ~1-epoch run.

Output: `/kaggle/working/adapter/` contains `adapter_config.json` + `adapter_model.safetensors`. The final cell zips them into `/kaggle/working/submission.zip`.

### 4. Run the CV kernel

The CV kernel has `aleixlopez/nemotron-sft-training` in its `kernel_sources`, so the training kernel's output is auto-mounted at `/kaggle/input/nemotron-sft-training/`. No manual attachment needed — just ensure the training kernel has completed at least one successful run, then **Run All** on `aleixlopez/nemotron-local-cv`.

Output: overall accuracy + per-label breakdown + `/kaggle/working/debug_predictions_with_labels.csv`.

### 5. Submit

In the Kaggle UI on the training kernel's output, click **Submit to Competition** and select `submission.zip`. (Or use `uv run kaggle competitions submit -c nvidia-nemotron-model-reasoning-challenge -f <local-path-to-zip> -m "..."` after downloading the zip — but pushing from the kernel output is faster.)

## Blackwell gotchas (load-bearing)

Both kernels import `kaggle/blackwell_setup.py` which encapsulates these:

- `PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True` set **before** torch import (reduces 30B fragmentation).
- `rmsnorm_fn` replaced with a pure-PyTorch implementation in every `modeling_nemotron_h*` module (the Triton kernel crashes on Blackwell SMs).
- `is_fast_path_available = False` patched in every `modeling_nemotron_h*` module **after** model load.
- `TRITON_PTXAS_BLACKWELL_PATH=/tmp/ptxas-blackwell` env var; if the `ptxas-blackwell` binary isn't already at that path, attach the public `metric/nvidia_metric_utility_script` kernel as a data source and `tar xf` it into `/tmp`.

If a training run crashes inside Triton or with a CUDA fast-path assert, the most likely cause is the post-load patches running too early (before the model is loaded) or not at all.

## Cost / quota discipline

- Free within Kaggle's GPU quota (RTX PRO 6000 Blackwell tier is metered; check the user's account page for current per-week budget).
- Sessions cap at 12 hr on this accelerator; our SFT run is 1-3 hr so we have headroom.
- Local CV is 30-60 min depending on how aggressively we set `max_num_seqs` / `gpu_memory_utilization` (defaults in `host_metric.py` mirror the host eval verbatim).

## Submission discipline

- **Never submit without local-CV first.** The host eval is the source of truth for the metric; our local CV is a byte-for-byte mirror of it. If local CV says 0.45 and we submit anyway, we burn one of the daily submission slots.
- Kaggle limits submissions per day; check via `uv run kaggle competitions submissions nvidia-nemotron-model-reasoning-challenge`.
